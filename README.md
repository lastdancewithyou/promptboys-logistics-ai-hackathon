# AI 기반 해상운송 의사결정 지원 시스템

> **물류 AI 아이디어 구현 해커톤 CHALLENGE 2026**
> 주최: 국토교통부 · 물류진흥재단

본 프로젝트는 이처럼 분산된 정보를 여러 AI 에이전트가 역할별로 분석하고, 실무자가 비교·검토할 수 있는 세 가지 해상운송 전략으로 정리하는 의사결정 지원 서비스입니다.

## 프로젝트 개요

사용자가 출발항·도착항, 희망 출항일, 화물 정보와 컨테이너 수량 등 해상 견적 의뢰서를 입력하면 멀티 에이전트 파이프라인이 다음 과정을 수행합니다.

1. 해상운임과 외부 시장 위험 등 환경 분석
2. 선사별 운항 스케줄 및 선복·비용·적재 가능 여부 검증
3. 과거 계약 이력 조회를 통한 비교 분석
4. 비용 최적, 최단 도착, 균형형 총 3가지 전략 제안
5. AI의 최적 선택을 보완하는 자연어 대화 기반 Navigator

AI가 예약을 자동 확정하는 것이 아니라, 판단 근거와 대안을 제공하고 최종 결정은 물류 담당자가 내리는 **Human-in-the-loop** 방식을 지향합니다.

## 핵심 기능

- **통합 견적 요청**: 항로, 일정, 화물, 위험물 및 적재 조건 등의 해양 견적서 입력
- **시장 조사 자동화**: SCFI 추세, WTI 기반 연료비 압력, 과거 계절 기상, 해운 뉴스 분석
- **선사 후보 검증**: HMM·MSC·MAERSK 선사 스케줄과 선복, 중량, CBM, 위험물 수용 여부 및 운임 비교
- **3가지 전략 제안**: `LOWEST_COST`, `FASTEST_ARRIVAL`, `BALANCED`와 AI 선호안 제공
- **설명 가능한 의사결정**: 모든 후보의 선정·미선정 근거를 보존하여 “왜 이 대안은 제외되었는가?”에 답변
- **실무자 피드백 반영**: Telegram을 통한 승인·거절, 추가 설명 요청 및 변경 조건 기반 재계획 -> 현재는 Telegram 기반이며, 향후에는 웹 내 Navigator로 통합하는 것이 목표"
- **진행 현황 시각화**: 에이전트별 처리 상태와 시장 위험, 추천 전략을 웹 대시보드에서 확인

## 구현 원리

```text
웹 견적 요청
    ↓
n8n Webhook · 요청 ID 및 진행 상태 생성
    ↓
┌──────────────────────┐   ┌──────────────────────┐
│ Market Intelligence  │   │ Carrier Evaluation   │
│ SCFI·WTI·기상·뉴스    │   │ 스케줄·비용·선복 검증 │
└──────────┬───────────┘   └──────────┬───────────┘
           └────────────┬─────────────┘
                        ↓
                 Strategy Agent
          과거 계약 이력 조회 · 전체 후보 평가
                        ↓
        비용 최적 · 최단 도착 · 균형형 전략 제안
                        ↓
       웹 대시보드 표시 · Telegram 담당자 검토
                        ↓
             승인 / 설명 요청 / 재계획
```

### 에이전트 구성

| 에이전트 | 역할 |
| --- | --- |
| Market Intelligence Agent | SCFI, WTI, 과거 기상과 최신 해운 이슈를 종합해 비용 압력과 시장 위험을 평가합니다. |
| Carrier Evaluation Agent | 선사별 스케줄을 수집하고 출항일, 선복, 중량, 부피 및 위험물 조건을 기준으로 실행 가능한 후보를 선별합니다. |
| Strategy Agent | 현재 후보와 시장 분석, 과거 계약 실적을 함께 비교해 세 가지 전략과 후보별 선정 근거를 생성합니다. |
| Explanation / Replan Agent | 담당자의 질문에 기존 결정 근거로 답변하고, 일정·예산·항로 조건이 바뀌면 재평가 또는 재탐색을 수행합니다. |

에이전트 출력은 구조화된 JSON으로 제한하고, 시장 지표를 실제 운임으로 임의 환산하거나 확인되지 않은 비용·위험을 생성하지 않도록 프롬프트와 후처리 규칙을 적용했습니다.

## 기술 구성

- **Frontend**: React 19, TypeScript, Vite, Tailwind CSS
- **AI Workflow**: n8n, OpenAI Chat Model, Structured Output Parser
- **Data & Tools**: Google Sheets, SCFI, WTI API, 기상 API, 해운 뉴스 RSS
- **Interaction**: Webhook 기반 상태 조회, Telegram Human-in-the-loop

## 프로젝트 구조

```text
src/
├── api/agentApi.ts                 # n8n 요청 및 파이프라인 상태 연동
├── components/
│   ├── QuotationInputView.tsx      # 견적 요청 입력
│   ├── AgentPipelineView.tsx       # 에이전트 진행 상태와 시장 분석
│   ├── StrategySelectionView.tsx   # 전략 비교 및 선택
│   └── ContractSearchView.tsx      # 과거 계약 자료 조회
├── App.tsx                         # 화면 단계 및 상태 관리
└── types.ts                        # 공통 데이터 타입
```
